## Key codebase findings

- The only deterministic, replayable execution path for tool-calling is in `il_toolcalling_core/engine.py` (`ToolCallTrace`, `replay` at lines 41–131). This is the foundation: everything we branch is built on top of `replay`.
- `score_trajectory` (`engine.py:138–197`) currently only accepts a raw `response: str`. Counterfactuals need a `score_trace(task, trace)` path that works on an already-replayed `ToolCallTrace`.
- `ToolCallingTask` (`il_toolcalling_core/tasks.py:11–26`) has no `faults` field. Faults are currently encoded in tool-function closures, e.g. `tool_error_recovery_v1/tasks.py:14–43`. Closure state means the *same* task object is not safely replayable many times in one process; we need to move fault state into `trace.state` or `task.faults`.
- `grade_tool_calling` (`iloptimus/core/grader.py:438–460`) and `build_prompt` (`grader.py:575–604`) are the public entry points; new engines should reuse `score_response` / `score_trajectory` rather than re-implement grading.
- An existing coding-only recombination environment lives at `iloptimus/core/rl_factory/environments/trajectory_recombination.py:346–498` (AST-based function splicing). It is **not** reusable for tool-calling traces; the new `trajectory_recombination.py` in `iloptimus/core/` must operate on `ToolCallTrace` segments and replay them through the simulator.
- `rl_factory/environments/environment_mutation.py:373–423` (`DynamicsMutator`) already mutates coding prompts/tests; the gap-learner depends on a new `ToolEnvMutator` (or `iloptimus/core/env_mutator.py`) that mutates `ToolCallingTask` init/tools instead of code strings.
- `stateful_environments.py:226–268` shows the right mental model: an action changes `state`, and the trajectory is a list of `(action, observation)` pairs. Tool-calling is the same, but actions are `<tool>` JSON blocks.

## 1. Prior art summary

### Counterfactual RL / off-policy evaluation
Off-policy estimators (importance sampling, doubly robust, counterfactual regret / CFR) reweight observed trajectories to estimate what another policy would have done. For Optimus, the simulator is deterministic and the “policy” is a fixed string of tool calls, so **we do not need importance-sampling weights** — we can replay the exact same calls under modified conditions and read the outcome. What we steal: the *question* (“what action at what step changes the return?”) and the cheap data-multiplication idea; what we replace is the statistical estimator with a deterministic `replay`.

### World models for branching (Dreamer, MuZero, JEPA)
Dreamer/MuZero/JEPA learn latent transition models so the agent can unroll futures in imagination. For tool-calling, the “world model” is already explicit: `ToolSpec.fn` maps `(state, args) -> (result, observation)`. The minimal version is **not** a neural network; it is the existing simulator. We branch by editing the call sequence or overriding tool behavior, then call `replay`. What we steal: the branching concept. What we skip: learned latent dynamics.

### Trajectory / plan recombination (Tree-of-Thoughts, Graph-of-Thoughts, MCTS, rStar, TS-LLM)
ToT/GoT maintain a tree of partial reasoning states; rStar uses MCTS + a discriminator; TS-LLM learns a value function for AlphaZero-style tree search. For us, the “thoughts” are tool calls, the “tree” is the branch set generated by the counterfactual engine, and the “value function” is the simulator score. What we steal directly: splice partial trajectories at subgoal boundaries and use the simulator as a search/evaluator. This is the most directly applicable family.

### Population-based training (PBT)
PBT keeps a population of agents, copies weights/hyperparameters from good performers, and mutates them. For trajectories, the analogous operation is: maintain a population of spliced call sequences, select by simulator score, crossover at phase boundaries, and mutate by swapping a segment. What we steal: the population loop and exploit/explore mutation operators.

### Contrastive RL / learning from the gap
Methods like GCR, TW-CRL, and ConSpec learn from the *difference* between success and failure trajectories, locating critical states that separate them. For tool-calling, the gap is usually a missing “read/check” before an “act.” What we steal: the diff algorithm and the curriculum-generation step that builds 100 variations where that missing constraint is decisive.

### DAgger / expert demonstration splicing
DAgger rolls the current policy, lets an expert correct it, and adds the corrected trajectory to the dataset. We do the same thing in simulation: when a spliced or counterfactual replay outperforms the model’s original rollout, we treat the better trace as a synthetic expert demonstration and add it to the SFT/GRPO training buffer.

### LLM self-consistency / self-improvement (STaR, RISE, ScPO)
These methods reuse on-policy rollouts: generate many responses, keep the consistent/high-scoring ones, and fine-tune on them. What we add is counterfactual *negatives* and *branches*, not just best-of-N: each rollout becomes many labeled prefix→outcome examples, which is exactly the “1 rollout → 10 counterfactuals → 100 derived states → 1000 training signals” target.

## 2. Counterfactual branching algorithm

### 2.1 New engine API

Add to `il_toolcalling_core/engine.py`:

```python
from dataclasses import dataclass, field
from typing import Any, Callable
import copy

@dataclass
class CallMod:
    kind: str  # "replace", "delete", "insert", "tool_override",
               # "state_patch", "delay_fault", "skip_fault"
    idx: int | None = None               # position in original call list
    call: dict[str, Any] | None = None   # for replace/insert
    tool_name: str | None = None         # for tool_override / fault
    override: Callable[[dict, dict], tuple[Any, str]] | None = None
    state_patch: dict[str, Any] | None = None
    from_idx: int | None = None          # fault source call index
    to_idx: int | None = None            # fault target call index

@dataclass
class FaultSpec:
    tool: str
    kind: str  # "fail_first_n", "wrong_value", "timeout", "delayed"
    params: dict[str, Any] = field(default_factory=dict)
```

The central new functions:

```python
def replay_with_modifications(
    task: ToolCallingTask,
    source: str | ToolCallTrace,
    mods: list[CallMod],
) -> ToolCallTrace:
    """Deterministically replay `source` (a response string or an existing
    ToolCallTrace) with `mods` applied. Returns a fresh ToolCallTrace.
    State is deep-copied from `task.init` so branches do not contaminate each other.
    """
```

```python
def score_trace(
    task: ToolCallingTask,
    trace: ToolCallTrace,
    answer: str | None = None,
    *,
    mode: Literal["full", "goal_only"] = "full",
) -> tuple[float, dict]:
    """Score an already-replayed trace. `mode="goal_only"` ignores the
    `<answer>` string; use this for cheap counterfactuals where the answer
    is from the original rollout and may not match a changed observation.
    """
```

Implementation notes for `replay_with_modifications`:
1. If `source` is a `ToolCallTrace`, copy its `calls` and `answer`; if it is a `str`, parse it.
2. `trace.state = copy.deepcopy(task.init)` (deep copy prevents nested `files` dict from leaking across branches, fixing the shallow-copy issue in the current `replay`).
3. Apply `state_patch` mods first.
4. Walk through calls by original index. Before processing index `i`, insert any `insert` mods with `idx==i`.
5. For `delete` mods with `idx==i`, skip the original call.
6. For `replace` mods with `idx==i`, use the replacement call.
7. For `tool_override` mods, if `idx` matches or `tool_name` matches the current call, use `override(state, args)` instead of `tool.fn`.
8. For `skip_fault` / `delay_fault`, construct an `override` that counts how many times `tool_name` has been invoked and injects the fault only at the desired call index. This lets us remove or delay faults without touching tool closures.

`score_trace` reuses the same selection and efficiency logic as `score_trajectory`, but it takes an existing `ToolCallTrace`. For `goal_only` mode it returns `correctness = 1.0 if goal_reached else 0.0` and ignores `answer_ok`.

Add to `ToolCallingTask` (`il_toolcalling_core/tasks.py`):

```python
faults: list[FaultSpec] = field(default_factory=list)
```

### 2.2 Branch types

#### A. “Remove a fault” counterfactual
Given `task.faults` (or a fault detected from observations, e.g. a returned 429/500), create a branch where that fault is disabled.

```python
def branch_remove_fault(self, fault: FaultSpec) -> ToolCallTrace:
    """Replay the same tool calls but override `fault.tool` so the fault
    never fires. If the original rollout succeeds despite the fault, this
    tells us the model over-came it; if it fails without the fault, the
    model was relying on the fault's absence (or the fault is irrelevant).
    """
    return replay_with_modifications(
        self.task, self.trace,
        [CallMod(kind="tool_override", tool_name=fault.tool,
                 override=self._no_fault_override(fault))]
    )
```

`_no_fault_override` returns the tool’s normal success observation, bypassing the fault logic. Because the rest of the call sequence is unchanged, this is **cheap** (no model call).

#### B. “Second-best action” counterfactual
At each decision index `i`, replace the call with the next-most-likely candidate and replay the rest unchanged.

```python
def branch_second_best(self, idx: int, k: int = 3) -> list[tuple[dict, ToolCallTrace, float, dict]]:
    alts = self._candidate_calls(self.trace.calls[idx], k)
    results = []
    for alt in alts:
        cf = replay_with_modifications(
            self.task, self.trace,
            [CallMod(kind="replace", idx=idx, call=alt)]
        )
        score, info = score_trace(self.task, cf, mode="goal_only")
        results.append((alt, cf, score, info))
    return results
```

Candidate generation:

```python
def _candidate_calls(self, call: dict, k: int) -> list[dict]:
    # If the model API exposes token logprobs at each <tool> position,
    # use the top-k tool-name predictions.
    if self.model and hasattr(self.model, "top_k_tool_names"):
        names = self.model.top_k_tool_names(self.response, call, k)
    else:
        # Cheap fallback: all non-distractor tools in the task.
        names = [
            n for n, spec in self.task.tools.items()
            if n != call["name"] and not spec.distractor
        ]
    candidates = []
    for name in names[:k]:
        new_args = {p: v for p, v in (call.get("args") or {}).items()
                    if p in self.task.tools[name].params}
        candidates.append({"name": name, "args": new_args})
    return candidates
```

The default `k=3`. If the original trajectory has `n` calls, this generates at most `n * k` cheap branches. **This does not re-query the model**; it replays the same suffix.

#### C. “Delayed onset” counterfactual
Move a fault from its original call index `f` to a later index `t`. Useful for “what if the 429 happened after the first retry instead of before?”

```python
def branch_delayed_fault(self, fault: FaultSpec, from_idx: int, to_idx: int) -> ToolCallTrace:
    return replay_with_modifications(
        self.task, self.trace,
        [CallMod(kind="delay_fault", tool_name=fault.tool,
                 from_idx=from_idx, to_idx=to_idx,
                 override=self._delayed_fault_override(fault, to_idx))]
    )
```

This is **cheap**.

### 2.3 Branching factor & scoring

| Branch type | cost | branching factor | scoring |
|---|---|---|---|
| Remove fault | cheap | 1 per `FaultSpec` | `score_trace(..., mode="goal_only")` — did the same call sequence still reach the goal? |
| Second-best action | cheap | `n_calls * k` (default `k=3`) | `score_trace(..., mode="goal_only")` — did one swapped call flip the outcome? |
| Delayed fault | cheap | per fault, a small set of `to_idx` offsets (e.g. +1, +2, +5, +10) | `score_trace(..., mode="goal_only")` |
| Full continuation from branch point | **expensive** | only for critical points selected above | prompt the model with the prefix + modified call and let it finish; score the new response with `score_trace(..., mode="full")` |

Cheap branches are scored by **goal reached, not answer correctness**, because the `<answer>` string came from the original rollout and may refer to observations that changed in the branch. Expensive full-continuation branches are scored normally.

### 2.4 “1 → 10 → 100 → 1000” expansion

One rollout with `n` calls and `f` faults:

- Generate `~10` environment branches (remove each fault, delay each fault, swap `~k` critical calls).
- Each branch is itself a full `ToolCallTrace` with `n` calls and `n+1` state snapshots → `~100` derived `(state, action, next_state, reward)` transitions.
- From each branch and each call we extract a `(prefix, chosen_action, outcome)` training signal: success/failure label, preference over actions, or value target → `1000` labeled examples per rollout.

## 3. Critical decision point identification

The goal is to compress a 200-call trajectory to ~12 calls that actually matter.

```python
@dataclass
class CriticalPoint:
    idx: int
    original: dict
    alternative: dict
    baseline_ok: bool
    cf_ok: bool
    cf_score: float

@dataclass
class CriticalTrace:
    trace: ToolCallTrace
    points: list[CriticalPoint]
    baseline_score: float
    baseline_ok: bool

    def compressed_calls(self) -> list[dict]:
        return [self.trace.calls[p.idx] for p in self.points]
```

Algorithm:

```python
class CounterfactualEngine:
    def __init__(self, task, response: str | None = None,
                 trace: ToolCallTrace | None = None, model=None):
        self.task = task
        self.response = response
        self.trace = trace or replay(task, response)
        self.model = model
        self.baseline_score, self.baseline_info = score_trace(task, self.trace)
        self.baseline_ok = bool(self.baseline_info["goal_reached"])

    def critical_points(self, max_candidates: int = 3,
                        max_points: int = 12) -> CriticalTrace:
        points = []
        for i, call in enumerate(self.trace.calls):
            for alt in self._candidate_calls(call, max_candidates):
                cf = replay_with_modifications(
                    self.task, self.trace,
                    [CallMod(kind="replace", idx=i, call=alt)]
                )
                _, info = score_trace(self.task, cf, mode="goal_only")
                cf_ok = bool(info["goal_reached"])
                if cf_ok != self.baseline_ok:
                    points.append(CriticalPoint(
                        idx=i, original=call, alternative=alt,
                        baseline_ok=self.baseline_ok, cf_ok=cf_ok,
                        cf_score=info.get("final_score", 0.0)
                    ))
                    break
            if len(points) >= max_points:
                break
        return CriticalTrace(self.trace, points, self.baseline_score, self.baseline_ok)
```

Why this works: if swapping one call flips the terminal outcome, that call is a bottleneck. The rest of the trajectory is irrelevant for credit assignment around that step. We keep only these calls for downstream replay/critic training.

Output usage:
- **For the model:** train a critic that predicts `cf_ok` from `(prefix, action)` at each critical point.
- **For the data pipeline:** store the compressed trace as a high-value demonstration; the 188 non-critical calls are training noise and can be masked.

## 4. Trajectory recombination algorithm

### 4.1 Segment alignment by subgoal

The hard part is aligning trajectories of different lengths/tools. We use the **expert trajectory** as the subgoal scaffold.

```python
@dataclass
class SubgoalSpec:
    name: str
    target_tools: set[str]
    required_args: set[str] = field(default_factory=set)

    def satisfied_at(self, trace: ToolCallTrace, start: int = 0) -> int | None:
        for i in range(start, len(trace.calls)):
            call = trace.calls[i]
            if call.get("name") in self.target_tools:
                if not self.required_args:
                    return i
                args = call.get("args") or {}
                if self.required_args.issubset(args.keys()):
                    return i
        return None
```

Subgoal derivation from `task.expert`:

```python
PHASE_CATEGORIES = {
    "explore": {"list", "dir", "ls", "search", "grep", "find", "scan", "navigate"},
    "read":    {"read", "get", "fetch", "show", "inspect", "describe", "query"},
    "act":     {"write", "update", "set", "patch", "submit", "commit", "create"},
    "verify":  {"verify", "check", "test", "confirm", "validate"},
}

def _tool_phase(tool_name: str, desc: str) -> str:
    name_desc = (tool_name + " " + desc).lower()
    for phase, keywords in PHASE_CATEGORIES.items():
        if any(k in name_desc for k in keywords):
            return phase
    return tool_name  # fallback: one phase per unique tool
```

For each `(tool, args)` in `task.expert`, create a `SubgoalSpec` whose `name` is the phase, whose `target_tools` starts with `{tool}` and can optionally be expanded by synonyms, and whose `required_args` is `set(args.keys())`.

Segmenting a trace:

```python
def segment_trace(self, trace: ToolCallTrace) -> list[list[dict]]:
    boundaries = [0]
    start = 0
    for sg in self.subgoals:
        idx = sg.satisfied_at(trace, start)
        if idx is None:
            # Agent missed this subgoal; keep start (will produce empty segment)
            idx = start
        boundaries.append(idx)
        start = idx
    boundaries.append(len(trace.calls))
    return [
        trace.calls[boundaries[i] : boundaries[i + 1]]
        for i in range(len(boundaries) - 1)
    ]
```

Because boundaries are defined by the *first* call that reaches each subgoal, segments from different agents are aligned by phase, not by raw index.

### 4.2 Splicing & replay

A “genome” is a list `agent_indices: list[int]`, one per segment. To build the spliced call list:

```python
def build_spliced(self, genome: list[int]) -> list[dict]:
    calls = []
    for seg_idx, agent_idx in enumerate(genome):
        calls.extend(self.segments[agent_idx][seg_idx])
    return calls
```

Then replay:

```python
def score_genome(self, genome: list[int]) -> tuple[float, ToolCallTrace]:
    calls = self.build_spliced(genome)
    response = calls_to_response(calls, answer="")  # answer is ignored in goal_only
    trace = replay(self.task, response)
    score, info = score_trace(self.task, trace, mode="goal_only")
    return score, trace
```

`calls_to_response` wraps each call in `<tool>{json}</tool>` and appends a dummy `<answer>`.

### 4.3 Genetic search

```python
class GeneticSplicer:
    def __init__(self, task, traces, pop_size=32, generations=10,
                 mutate_rate=0.15, crossover_rate=0.5):
        self.task = task
        self.recombiner = TrajectoryRecombiner(task, traces)
        self.pop_size = pop_size
        self.generations = generations
        self.mutate_rate = mutate_rate
        self.crossover_rate = crossover_rate

    def search(self) -> tuple[list[int], float, ToolCallTrace]:
        n_agents = len(self.recombiner.traces)
        n_segments = len(self.recombiner.segments[0])
        pop = [
            [random.randrange(n_agents) for _ in range(n_segments)]
            for _ in range(self.pop_size)
        ]
        for gen in range(self.generations):
            scored = [(g, self.recombiner.score_genome(g)[0]) for g in pop]
            scored.sort(key=lambda x: x[1], reverse=True)
            next_gen = [scored[0][0]]  # elitism
            while len(next_gen) < self.pop_size:
                p1, p2 = self._tournament_select(scored), self._tournament_select(scored)
                child = p1[:]
                if random.random() < self.crossover_rate:
                    pt = random.randint(1, n_segments - 1)
                    child = p1[:pt] + p2[pt:]
                if random.random() < self.mutate_rate:
                    seg = random.randrange(n_segments)
                    child[seg] = random.randrange(n_agents)
                next_gen.append(child)
            pop = next_gen
        best = max(pop, key=lambda g: self.recombiner.score_genome(g)[0])
        score, trace = self.recombiner.score_genome(best)
        return best, score, trace

    def _tournament_select(self, scored, k=3):
        return random.choice(random.sample(scored, k=min(k, len(scored))))[0]
```

Selection is by `score_trace(..., mode="goal_only")`. If the spliced sequence fails because preconditions are not met, the score will be 0 and it is discarded. The genetic search naturally learns to compose only compatible segments.

Why this is not hidden-state splicing: we splice **plans, actions, tools, subgoals, and reasoning states** (calls + observations), not model activations or weights. The simulator re-derives the true state from the calls.

## 5. Learn-from-gap algorithm

### 5.1 Trace diff

```python
@dataclass
class GapAnalysis:
    first_divergence_idx: int
    tools_only_in_pass: list[str]
    tools_only_in_fail: list[str]
    arg_differences: list[ArgDiff]
    hidden_constraint: ConstraintSpec | None

@dataclass
class ConstraintSpec:
    kind: str  # "read_before_write", "check_before_submit", "auth_before_fetch"
    read_tool: str | None
    read_args: dict[str, Any] | None
    act_tool: str
    act_args: dict[str, Any] | None
    explanation: str
```

Algorithm:

```python
class GapLearner:
    def analyze(self, pass_trace: ToolCallTrace, fail_trace: ToolCallTrace,
                task: ToolCallingTask) -> GapAnalysis:
        # 1. first divergence
        n = min(len(pass_trace.calls), len(fail_trace.calls))
        first_div = next(
            (i for i in range(n)
             if not self._calls_equal(pass_trace.calls[i], fail_trace.calls[i])),
            n
        )

        # 2. set differences
        pass_tools = {c["name"] for c in pass_trace.calls[first_div:]}
        fail_tools = {c["name"] for c in fail_trace.calls[first_div:]}

        # 3. argument diffs for matching tool names
        arg_diffs = []
        for i in range(n):
            a, b = pass_trace.calls[i], fail_trace.calls[i]
            if a["name"] == b["name"]:
                for k in set(a.get("args", {})) | set(b.get("args", {})):
                    if a.get("args", {}).get(k) != b.get("args", {}).get(k):
                        arg_diffs.append(ArgDiff(i, a["name"], k,
                                                  a.get("args", {}).get(k),
                                                  b.get("args", {}).get(k)))

        # 4. hidden-constraint detection
        constraint = self._find_hidden_constraint(
            pass_trace, fail_trace, first_div, task
        )

        return GapAnalysis(
            first_divergence_idx=first_div,
            tools_only_in_pass=sorted(pass_tools - fail_tools),
            tools_only_in_fail=sorted(fail_tools - pass_tools),
            arg_differences=arg_diffs,
            hidden_constraint=constraint,
        )

    def _calls_equal(self, a, b) -> bool:
        return a.get("name") == b.get("name") and a.get("args") == b.get("args")
```

### 5.2 Hidden-constraint detection

```python
def _find_hidden_constraint(self, pass_trace, fail_trace, div, task):
    # Find an act step in the failing trace that succeeds only after a read in the passing trace
    act_tools = {n for n, spec in task.tools.items()
                 if self._tool_phase(n, spec.description) == "act"}
    read_tools = {n for n, spec in task.tools.items()
                  if self._tool_phase(n, spec.description) == "read"}

    for i in range(div, len(fail_trace.calls)):
        fcall = fail_trace.calls[i]
        if fcall["name"] in act_tools:
            # Look just before this act in the passing trace for a read of the same target
            for j in range(max(0, i - 3), i):
                pcall = pass_trace.calls[j] if j < len(pass_trace.calls) else None
                if pcall and pcall["name"] in read_tools:
                    if self._same_target(pcall, fcall):
                        return ConstraintSpec(
                            kind="read_before_write",
                            read_tool=pcall["name"],
                            read_args=pcall.get("args", {}),
                            act_tool=fcall["name"],
                            act_args=fcall.get("args", {}),
                            explanation=f"{pcall['name']} on the target is required before {fcall['name']}"
                        )
    return None

def _same_target(self, read_call, act_call) -> bool:
    # Simple heuristic: at least one argument key (e.g. path/dataset_id) matches
    rargs = read_call.get("args") or {}
    aargs = act_call.get("args") or {}
    return bool(set(rargs.values()) & set(aargs.values()))
```

This captures e.g. `read_file` before `write_file` in `tool-fs`, or `authenticate` before `fetch_records` in `tool-pipeline`.

### 5.3 Variation generation

`GapLearner` delegates to `ToolEnvMutator` (`iloptimus/core/env_mutator.py`, or the existing `DynamicsMutator` extended for tool worlds):

```python
class ToolEnvMutator:
    def __init__(self, base: ToolCallingTask):
        self.base = base

    def generate_variations(self, constraint: ConstraintSpec, k: int = 100) -> list[ToolCallingTask]:
        """Return k variants of `base` where `constraint` is necessary."""
        strategies = [
            self._add_decoys,
            self._require_read_before_act,
            self._randomize_target,
            self._inject_verify_fault,
        ]
        variants = []
        for i in range(k):
            strategy = strategies[i % len(strategies)]
            variants.append(strategy(constraint, strength=0.5 + 0.5 * (i // len(strategies))))
        return variants
```

Concrete strategies:

- **Add decoys:** if the constraint is `read_file` before `write_file`, add extra fake files or fake config sections so the agent cannot guess the correct write target/content without reading.
- **Require read before act:** patch the act tool (`write_file`, `submit`, etc.) to return an error unless a key in `state` shows the read tool was called with the matching target.
- **Randomize target:** change the correct value/parameter in the environment so it can only be discovered by the read tool (e.g., the correct port to write is chosen randomly per episode and stored in a file).
- **Inject verify fault:** after an incorrect act, inject an observation that reveals the missing read was needed; this creates an error-recovery subgoal.

These are all deterministic and replayable, so they become new training episodes for the model.

## Implementation priorities

1. **Engine changes first**: `CallMod`, `replay_with_modifications`, `score_trace`. This unlocks everything else and must not break `smoke_toolcalling.py`.
2. **Counterfactual engine**: branch types and `critical_points()`.
3. **Trajectory recombination**: `SubgoalAligner` + `GeneticSplicer`.
4. **Gap learner + ToolEnvMutator**: depends on (3) and on `env_mutator` design doc.
5. **Wire into RSI loop**: in `iloptimus/core/rsi_loops.py` add a `loop-counterfactual-curriculum` and `loop-gap-learner` template that uses these engines.

## Risks & mitigations

- **Closure-based tool state** (`tool_error_recovery_v1` counters) makes replay non-idempotent. Mitigation: move fault state into `trace.state` / `FaultSpec` and use `copy.deepcopy(task.init)`; update `tool_error_recovery_v1` to read counters from `state`.
- **Answer mismatch in cheap counterfactuals**: use `score_trace(..., mode="goal_only")` for environment branches; only full continuations use `mode="full"`.
- **Segment alignment failures**: genetic search naturally drops incompatible splices because they replay to score 0.
- **Over-fitting to the simulator**: tool-calling tasks are designed so the simulator *is* the truth; the risk is low. For future neural-world-model branches, this design separates the engine API cleanly.
